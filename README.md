# Персональний помічник

Консольний застосунок для ведення адресної книги та окремих особистих нотаток.
Проєкт створюється відповідно до ТЗ курсу Python Programming (Neoversity).

> Поточна версія — **узгоджений каркас розробки**. Логіка збереження та
> розрахунку найближчих днів народження вже є в коді. CRUD, валідація, CLI-
> сценарії й теги позначені безпосередньо в модулях як `TODO`.

## Можливості

Основна частина:

- створення, пошук, редагування та видалення контактів;
- зберігання імені, адреси, телефонів, email та дня народження контакту;
- перевірка телефону та email при додаванні й редагуванні;
- список майбутніх днів народження на задану кількість днів;
- створення, пошук, редагування та видалення текстових нотаток;
- збереження контактів і нотаток між перезапусками.

Додаткова частина:

- теги нотаток;
- пошук нотаток за тегом;
- сортування нотаток за тегами.

## Запуск

Потрібен Python 3.10 або новіший.

```bash
python3 main.py
```

Застосунок не має сторонніх залежностей.

## Структура проєкту

```text
.
├── main.py
├── commands.py
├── models.py
├── books.py
├── storage.py
├── upcoming_birthdays.py
├── README.md
```

| Модуль | Відповідальність |
| --- | --- |
| `main.py` | Точка входу, цикл CLI та прямий `match`-каскад команд. Не містить доменної логіки. |
| `commands.py` | Сценарії, які бачить користувач: діалог, вибір знайденого запису, форматування відповідей. |
| `models.py` | Data-моделі та валідація окремих полів. |
| `books.py` | Репозиторії в пам’яті: `AddressBook` і `NotesBook`; пошук і видалення. |
| `storage.py` | Збереження та завантаження обох репозиторіїв одним файлом. |
| `upcoming_birthdays.py` | Чиста функція розрахунку найближчих днів народження. |

Потік виконання:

```text
Користувач
  → main.py (введення та вибір команди)
  → commands.py (користувацький сценарій)
  → models.py / books.py (дані, валідація, пошук)
  → storage.py (збереження при виході)
```

## Архітектурні рішення

### Контакти й нотатки — незалежні

Адресна книга й нотатки є різними сутностями. Нотатка не належить контакту:
користувач може створити, наприклад, нотатку «Купити подарунок» без створення
контакту.

```text
AddressBook                       NotesBook
└── {contact_id: Contact}         └── {note_id: Note}
```

### Стабільні ідентифікатори

У кожного контакту й кожної нотатки є UUID. Пошук може повертати кілька
результатів, тому редагування та видалення завжди виконуються над конкретним
`id`, а не над першим випадковим збігом або текстом нотатки.

ID генерується в командному сценарії через `uuid.uuid4()` перед створенням
`Contact` або `Note`.

### Межі відповідальності

- `models.py` не читає `input()`, не друкує в консоль і не працює з файлами.
- `books.py` не знає про CLI та не друкує повідомлень.
- `commands.py` керує діалогом користувача і перетворює очікувані помилки на
  зрозумілі тексти.
- `main.py` лише запускає застосунок та маршрутизує команди.
- `storage.py` не реалізує бізнес-правила.

## Data-моделі

### `Field`

Базовий клас-обгортка над значенням поля. Спільний інтерфейс — `.value` та
`str(field)`.

### Поля контакту

| Клас | Правило |
| --- | --- |
| `Name` | Обов’язкове ім’я; пробіли на початку/кінці прибираються; порожнє значення заборонене. Українські й інші Unicode-символи дозволені. |
| `Phone` | Перед перевіркою прибираються пробіли, дужки та дефіси. Команда має зафіксувати один формат: 10 цифр або міжнародний формат на кшталт `+380...`. |
| `Email` | Пробіли прибираються, значення приводиться до нижнього регістру; валідується базова структура `name@domain.tld`. |
| `Address` | Непорожній рядок після нормалізації пробілів. Складна географічна валідація не потрібна. |
| `Birthday` | Рядок строго у форматі `DD.MM.YYYY`, який перетворюється на `datetime.date`. Некоректні дати відхиляються. |

### `Contact`

```python
class Contact:
    id: str
    name: Name
    phone: Phone | None
    email: Email | None
    address: Address | None
    birthday: Birthday | None
```

У контакту є один необов’язковий номер телефону, а також по одному email,
адресі й дню народження. Контакт не містить нотаток.

Методи, які треба реалізувати:

| Метод | Логіка |
| --- | --- |
| `set_phone(phone)` | Валідує номер і встановлює або замінює поточний номер. |
| `set_name(name)` | Валідує та оновлює ім’я. |
| `set_email(email)` | Валідує та встановлює/замінює email. |
| `set_address(address)` | Валідує та встановлює/замінює адресу. |
| `set_birthday(birthday)` | Валідує й встановлює/замінює дату народження. |
| `__str__()` | Повертає читабельне представлення всіх полів; відсутні поля відображаються як `—`, не як `None`. |

### `Note`

```python
class Note:
    id: str
    text: str
    tags: set[str]
```

Текст є обов’язковим. Теги — необов’язкова додаткова функція; вони зберігаються
як `set`, тому не дублюються.

| Метод | Логіка |
| --- | --- |
| `edit_text(text)` | Забороняє порожній текст і замінює попередній. |
| `add_tag(tag)` | Прибирає `#` і пробіли, приводить тег до нижнього регістру та додає без дублікатів. |
| `edit_tag(old_tag, new_tag)` | Перевіряє старий тег і замінює його нормалізованим новим. |
| `delete_tag(tag)` | Видаляє існуючий тег; за відсутнього тега повертає помилку. |
| `__str__()` | Показує id, текст і теги в алфавітному порядку. |

## Репозиторії

### `AddressBook`

Наслідує `UserDict` і зберігає записи у вигляді:

```python
{contact.id: contact}
```

| Метод | Логіка |
| --- | --- |
| `add(contact)` | Перевіряє дубль нормалізованого імені та додає контакт. |
| `find_by_id(contact_id)` | Повертає контакт за id або `None`. |
| `search(query)` | Шукає частковий збіг без урахування регістру в імені, телефоні, email, адресі та даті народження. Повертає весь список збігів. |
| `delete(contact_id)` | Видаляє саме вибраний контакт. Викликається лише після підтвердження користувача в команді. |
| `get_upcoming_birthdays(days)` | Перевіряє `days` і викликає функцію з `upcoming_birthdays.py`. |

### `NotesBook`

Також наслідує `UserDict`:

```python
{note.id: note}
```

| Метод | Логіка |
| --- | --- |
| `add(note)` | Додає нотатку за її id. |
| `find_by_id(note_id)` | Повертає нотатку за id або `None`. |
| `search(query)` | Шукає частковий збіг у текстах усіх нотаток без урахування регістру. |
| `search_by_tag(tag)` | Нормалізує тег і повертає всі нотатки з ним. |
| `sort_by_tags()` | Повертає всі нотатки, відсортовані за тегами; нотатки без тегів розміщує в кінці. |
| `delete(note_id)` | Видаляє нотатку за id. Викликається лише після підтвердження користувача в команді. |

## Команди користувача

Головне меню виводиться один раз під час запуску. Користувач працює в циклі до
команди `exit` або `close`.

### Основні команди

| Команда | Сценарій |
| --- | --- |
| `add-contact` | Інтерактивно запитує ім’я, телефон, email, адресу й день народження. Ім’я обов’язкове; необов’язкові поля можна пропустити. Некоректне поле перепитується без втрати вже введених даних. Після створення показується контакт і його id. |
| `change-contact <id або запит>` | Шукає контакт. За кількох збігів показує їх і просить вибрати id. Далі пропонує змінити `name`, `phone`, `email`, `address` або `birthday`. `set_phone` замінює поточний номер. |
| `find-contact <запит>` | Універсальний пошук за ім’ям, телефоном, email, адресою або днем народження. Показує усі збіги з id. |
| `delete-contact <id або запит>` | Знаходить один контакт, за кількох збігів просить id, показує обраний запис і запитує `Are you sure? (yes/no)`. Видаляє лише після `yes`. |
| `birthdays <days>` | Показує контакти, у яких день народження настане в межах `days` днів від сьогодні. |
| `add-note` | Інтерактивно отримує непорожній текст, створює незалежну нотатку та показує її id. |
| `find-note <запит>` | Шукає підрядок у текстах усіх нотаток; показує id, текст і теги. |
| `change-note <note_id>` | Знаходить нотатку за id та просить новий текст. Теги не змінює. |
| `delete-note <note_id>` | Показує нотатку, запитує `Are you sure? (yes/no)` і видаляє її лише після `yes`. |
| `exit` / `close` | Зберігає обидві книги й завершує застосунок. |

### Додаткові команди тегів

| Команда | Сценарій |
| --- | --- |
| `add-tag <note_id> <tag>` | Додає тег до вибраної нотатки. |
| `edit-tag <note_id> <old_tag> <new_tag>` | Замінює тег. |
| `delete-tag <note_id> <tag>` | Показує тег, запитує `Are you sure? (yes/no)` і видаляє його лише після `yes`. |
| `show-notes-by-tag <tag>` | Виводить усі нотатки із заданим тегом. |
| `sort-notes-by-tags` | Виводить всі нотатки, відсортовані за тегами. |

## Дні народження

`get_upcoming_birthdays(address_book, days)` уже реалізовано в
`upcoming_birthdays.py`.

Алгоритм:

1. Для кожного контакту з днем народження обчислюється найближча дата цього
   дня народження.
2. Якщо дата в цьому році вже минула, використовується наступний рік.
3. Для 29 лютого у невисокосний рік використовується 28 лютого.
4. Вибираються дати в межах від `0` до `days` включно.
5. Якщо дата привітання припадає на суботу або неділю, вона переноситься на
   понеділок.

Результат містить `id`, ім’я та дату привітання у форматі `DD.MM.YYYY`.

## Збереження даних

`storage.py` використовує стандартну бібліотеку `pickle` і один файл:

```text
~/assistant_data.pkl
```

У файл записується кортеж:

```python
(contacts, notes)
```

На першому запуску, коли файлу ще немає, `load_data()` повертає порожні
`AddressBook()` та `NotesBook()`.

Не завантажуйте сторонні `.pkl`-файли: `pickle` безпечний лише для даних, яким
ви довіряєте.

## Помилки та повідомлення

Очікувані помилки не повинні завершувати застосунок. `commands.py` має
перехоплювати помилки валідації, пошуку та некоректних аргументів і повертати
короткі повідомлення, наприклад:

```text
Некоректний номер телефону. Введіть 10 цифр або номер у форматі +380...
Контактів за запитом "Іван" не знайдено.
Нотатку з id "..." не знайдено.
```

Несподівані програмні помилки не слід мовчки приховувати загальним
`except Exception`.

## Необов’язкове розширення

Пункт ТЗ про визначення наміру користувача не входить у поточний каркас.
Його можна реалізувати після основного функціоналу: якщо команда невідома,
система порівнює введений текст із відомими командами та пропонує найближчу,
але не виконує її без підтвердження користувача.
